## Ответы на итоговые вопросы

1. **Атрибуты класса.** `_id_counter` в `BaseEntity` (счётчик общий для класса, в экземпляре каждый объект считал бы с нуля). Константы `USERNAME_*`, `FULL_NAME_*`, `CODE_LENGTH`, `NUM_CODE_LENGTH` (одинаковы для всех объектов). `URL`, `TIMEOUT`, `HEADERS` у поставщиков (настройки класса).

2. **Инкапсуляция.** `id` (скрыт в `__id`, снаружи свойство без сеттера), `created_at` (`_created_at` и свойство только для чтения), `is_active` (меняется только через `activate()` и `deactivate()`). Остальные поля защищены сеттерами с проверкой. Механизмы: соглашения об именах и `@property`.

3. **Иерархии.** `BaseEntity` → `User`, `Currency`: общий код сущностей (id, `created_at`, `to_dict()`, сравнение). `AppError` → `ValidationError`, `DuplicateError`, `NotFoundError`, `ProviderError`, `InactiveUserError`: все ошибки приложения ловятся одним `except AppError`.

4. **Полиморфизм.** Переопределение: `to_dict()`, `__str__`, `__repr__`. Абстрактный класс: `RateProvider` с тремя реализациями. Магические методы: `__eq__`, `__hash__`, `__lt__`. Самое полезное: `RateProvider`, новый источник курсов подключился без правок `services.py`.

5. **`Subscription` и `Rate` не наследуют `BaseEntity`.** Наследование нужно при отношении «является» и наличии собственного `id`. У подписки составной ключ `(user_id, currency_id)`, курс не хранится в БД.
